## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：对经过审核的 Method Unit 建立**文件/Git 版本化存储**与**本地 SQLite/FTS5 只读检索索引**，
  实现按资产版本**原子发布**、**全量重建**与**增量重索引**。
- **Context**：依赖 R06A；可复用方法包含源码、manifest、最小测试与来源证明；M03 已有平台 SQLite 元数据机制，
  但**方法原始源码仍保存在文件仓库**，索引只是**可丢弃的派生视图**。
- **Constraints**：检查现有目录后决定新增 `methods/`；索引保存
  `id/version/kind/language/framework/profile/tags/provides/description/asset_path/checksum` 等检索字段，
  **不以索引内容替代 manifest 校验**；构建使用**受控文件树**与事务/原子切换，**禁止跟随符号链接**扫描宿主敏感路径；
  不在数据库存密钥或未清洗的私有业务源码，**不引入向量库/远程索引服务**。
- **WhenDone**：≥3 个小型、可独立测试的示例方法资产；通过全量构建、增量更新、删除后重建、checksum 篡改拒绝、
  索引损坏恢复及并发读取测试；源码仓库不变时重建得到等价结果；MVP 回归 PASS。

## 输入 / 输出契约

- **方法仓库** `methods/<asset-id>/<semver>/`（建议路径）：`manifest.json`（`kind=method-unit`）+ `src/` + `tests/`。
  权威数据是源码与 manifest；目录可由 Git 版本化。
- **契约扩展（R06B）**：`MethodUnitManifest` 新增**必需** `language`/`framework` 与可选 `description`/`tags`
  （R06A 的 `symbol/signature/layer/source_provenance` 仍必需）；`language/framework/tags` 仅接受安全标识符。
- **`compute_checksum`** 现**跳过符号链接文件**（原有资产无变化，checksums 不变）。
- **`scan_methods(root)`** → `list[MethodRecord]`：受控遍历（不跟随符号链接、跳过隐藏目录），校验 `kind` 与
  checksum；非方法单元 → `ASSET_CONFLICT`，checksum 不符 → `ASSET_CHECKSUM_MISMATCH`。
- **`build_index(root, path)`** → `IndexBuildResult{count, revision, path}`：写临时库后 `os.replace` **原子发布**。
- **`update_index(root, path)`**：增量 upsert/delete；索引缺失或损坏 → 自动整库重建。
- **`search(query, *, path, limit)`** → 若干命中行：FTS5 关键词召回（查询规整为安全 AND 词项，避免 MATCH 注入）；
  **语义判定与兼容筛选归 R06C**。
- **`is_valid_index(path)`** / **`read_meta(path)`**：索引健康与 `index_schema_version`/`index_revision`/`asset_count`。
- **索引落点**：默认 `methods/.index/method-index.sqlite`（`*.sqlite` 已 gitignore），可用
  `AGENTFORGE_METHODS_ROOT` / `AGENTFORGE_METHOD_INDEX` 覆盖。CLI：`python -m agentforge_platform.method_index {build|update|checksums|search}`。

## 设计

- **派生视图原则**：索引只存检索字段与关系（`profiles/provides/requires/tags/acceptance_ids` 以 JSON 落列，
  另有 FTS5 虚表），**不存源码正文**；丢失即可从仓库重建（`index_revision` 由排序后的 (id, version, checksum)
  派生，源码不变则等价）。
- **受控扫描**：`os.walk(followlinks=False)` + 显式跳过**符号链接目录与文件**与隐藏目录（含 `.index`），
  避免读取宿主敏感路径；checksum 逐方法校验，篡改在构建期即拒。
- **原子发布**：构建先写同目录临时库（含 schema/数据/`index_meta`），`os.replace` 替换目标；
  任一环节失败不会用半成品覆盖已发布索引。
- **损坏恢复**：`is_valid_index` 校验表存在与 `index_schema_version`；`update_index` 检测到无效即整库重建。
- **并发只读**：写库开 WAL；`search`/`read_meta` 用 `mode=ro` URI 打开，多读者安全。
- **安全**：不存密钥/未清洗私有源码；查询经词项规整，杜绝 FTS 语法注入；不引入向量库/远程索引。

## 风险 / 下一步

- **索引未接入生成链路**：本轮只建仓库与索引；`Asset Finder`（精确检索/关键词召回/确定性兼容筛选）归 **R06C**，
  接入 Resolver/装配与 Asset Lock 归 **R06D**。
- **方法单元暂未注册进 `AssetRegistry`**：默认注册表根仍为 `templates/`+`capability-packs/`；
  方法单元由索引单独检索，R06C/D 决定如何统一消费（避免两套选择规则）。
- **示例方法为演示性质**：仅覆盖字段校验/日期处理/状态守卫，**不声称能覆盖任意业务**。
- **下一步 R06C**：实现 `Asset Finder`——从冻结 spec/contract/`acceptance_ids` 派生规范化能力查询，
  精确匹配 + FTS5 召回 + 确定性兼容筛选，返回 `EXACT/PARAMETERIZED/STRUCTURED_CANDIDATE/NO_MATCH` 与拒绝原因。
