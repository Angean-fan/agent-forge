# M15A｜阶段 B 生成资产安全补强

日期：2026-10-11
状态：完成

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：修复生成项目权限矩阵未落地、列表分页无上限等缺口，并收紧前端令牌与 Docker 构建上下文。
- **Context**：依赖 M10—M15；契约路由已有 `allowed_roles` 但 M11 Controller 只检查登录与归属；`size` 未限制；M09 前端把 JWT 存 `localStorage`；无 `.dockerignore`。
- **Constraints**：服务端按 `allowed_roles` 判定角色；空角色集合拒绝；契约权限矩阵与路由不一致时拒绝装配；`page/size` 有界、越界返回 4xx；前端令牌仅内存、不落 localStorage/sessionStorage；`.dockerignore` 在排除项与保留锁文件之间正确取舍；**不原地覆盖已发布资产**——新资产版本 + 新 checksum；Registry/装配器按资产锁定位新旧版本。
- **WhenDone**：变体契约（ADMIN 可写、MEMBER 只读）真实 HTTP 证明 403/读自己/跨用户拒绝/空角色不放行；分页零/负/过大被拒、合法边界可分页；前端刷新重登且令牌不落持久存储有测试；新版本构建/测试/checksum/`.dockerignore` 通过，旧资产与旧锁仍可校验。

## 资产版本化重构（不可原地覆盖）

```
templates/
  demo-0.1/   (原模板，保留不改)
  demo-0.2/   (新版本：内存令牌 + .dockerignore)
capability-packs/
  task-crud-backend/0.1.0/   0.1.1/   (0.1.1：角色判定 + 分页边界)
  task-crud-frontend/0.1.0/
```
- 注册表改为**递归扫描** manifest.json（剪枝构建目录），索引 `(kind,id,version)`。
- 解析器按 **profile 兼容 + 取最高版本** 选择（`_version_key`），并支持 `pins` 固定版本以复现旧锁。
- 装配器按锁清单里的 `kind/id/version` 定位资产，**不假定 templates/ 根只有一个版本**。

## 具体修复

1. **权限矩阵落地**：契约每条路由的 `allowed_roles` → 生成 Controller 每方法的 `requireAnyRole(...)`；空集合渲染为 `List.of()`（一律拒绝）；`build_params` 校验路由 `allowed_roles` 与权限矩阵一致，不一致 → `CONTRACT_CONFLICT`（拒绝装配）。原有数据归属校验保留。
2. **分页边界**：`list` 先 `validatePaging(page,size)`（`page≥1`、`1≤size≤100`），越界 → `400 BAD_REQUEST`，不把极大值交给分页查询。
3. **前端令牌**：`templates/demo-0.2` 的 `api/client.ts` 与 `stores/auth.ts` 改为**内存令牌**，刷新页面需重登；不写 localStorage/sessionStorage。
4. **`.dockerignore`**：backend/frontend 各一份，排除 `.env*`、`.git`、`target`/`node_modules`/`dist`、日志；**保留** `pom.xml`/`package-lock.json` 等构建锁文件。
5. **M14 补强**：`asset-lock.json` 纳入模板 compose 的 **MySQL 镜像 reference + digest**（`mysql:8.0.43@sha256:3e64…`）；compose 未锁 digest → 拒绝。
6. **A 阶段残余（文档 M28 行为）**：`auth.purge_expired_sessions` 批量清理过期会话，不影响有效会话。
7. **顺带修复**：checksum 排除 `.DS_Store`/`Thumbs.db`（此前 macOS 杂项文件污染 checksum 并被装配器复制）。
