# M11｜实现后端单实体 CRUD 能力包

日期：2026-10-11
状态：完成

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：为 `Task` 制作可参数化的后端 CRUD、分页、简单搜索与用户数据归属能力包。
- **Context**：依赖 M06、M09、M10；放入 `capability-packs/`；复用模板的 JWT/RBAC 与异常体系，不重复实现认证。
- **Constraints**：参数化字段和命名只能从经校验的 spec/contract 获取；成员访问他人数据必须服务端拒绝；不接受模型输出的 SQL 原样执行。
- **WhenDone**：用固定 Task 参数可生成并编译后端；成员 A 读取/修改 B 任务失败于授权层；分页总数字段与搜索行为有独立测试。

## 设计要点

1. **参数只能来自经校验的契约**：`build_params(contract)` 从 `BusinessContract` 派生实体名/表名/复数路由/列与 Java 类型/DTO 字段；不读取模型输出或任意字符串。归属列固定 `owner_id`（缺失即拒绝）。
2. **复用模板、不重复认证**：生成的 controller 依赖模板的 Spring Security JWT 鉴权与 `UserService`；异常统一走模板的 `ApiException/ErrorCode`。能力包只写 `owned_paths`（entity/mapper/service/controller/dto/vo/config/migration/test + pom 依赖注入点）。
3. **数据归属在服务端强制**：`requireOwned()` 加载记录后比对 `owner_id`，非本人抛 `403 FORBIDDEN`；列表查询固定 `eq(owner_id, 当前用户)`。前端隐藏不可替代。
4. **确定性渲染**：Jinja2（`StrictUndefined`）+ Python 预计算声明行；不注入模型 SQL。`render_pack` 复制基础模板到输出目录后渲染，**不改动原模板**。
5. **分页依赖由能力包携带**：MyBatis-Plus 3.5.17 的 `PaginationInnerInterceptor` 位于 `mybatis-plus-jsqlparser` 模块，故 manifest 声明该依赖并在渲染时注入模板 pom（同一 MyBatis-Plus 3.5.17 线，Profile 版本不变）。
