## 数据模型（技术文档第 4 节）

| 表 | 主要字段 | 约束 |
|---|---|---|
| `run` | id、project_id、spec_id、status、error_code、created_at、updated_at | project_id 索引；状态白名单 |
| `task` | run_id、task_id、status、attempt、output_hash | **UNIQUE(run_id, task_id)** |
| `event` | run_id、sequence、type、payload | **UNIQUE(run_id, sequence)**，sequence 单调 |
| `artifact` | run_id、path、sha256、kind、verified | **UNIQUE(run_id, path)**，属该 run 目录 |

## 状态机

白名单迁移（`ALLOWED_TRANSITIONS`）：

```
QUEUED → PLANNING → GENERATING → VERIFYING → SUCCEEDED
                 ↘          ↘          ↘
                  FAILED     FAILED     FAILED
```
（SUCCEEDED/FAILED 为终态；`FAILED` 记录 `error_code`；非法转移抛 `RUN_INVALID_TRANSITION`/409。）
`transition()` 只接受白名单内目标；状态即数据库权威值。完成态要求 M17/M18 全部必检（由 M23 生成图落实）。

## 其他

- **事件序号**：`append_event` 取该 run 现有最大 sequence + 1，逐 run 单调、从 1 起。
- **run 目录隔离**：`run_directory(work_root, run_id)` → `<work_root>/run-<id>`（按 id 构造，不接收任意路径）。
- **run 归属**：`require_run_owner` 经 `run.project_id → project.owner_id` 校验；缺失 404、非本人 403、未登录 401。
