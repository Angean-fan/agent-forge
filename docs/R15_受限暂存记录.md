## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：让编码任务**只能读取**授权源码/只读契约，**写入**当前 run/task 专属**暂存目录**；提交前生成 `FileChangeSet`。
  （本次确认：提交**原子应用到 run 源码树**，失败回滚。）
- **Context**：依赖 M15/M16、R13/R14；技术文档第 4、6 节定义 `allowed_paths`、基准 hash、临时区、受保护文件与原子提交。
- **Constraints**：文件 backend 在**每次读写时**执行权限/路径检查，最终提交再校验；拒绝 `..`、绝对路径、符号链接逃逸、过大文件、
  认证模板、`asset-lock.json` 和固定验收断言修改；Agent 不得修改版本化方法仓库、Registry、FTS5 索引或发布队列；
  只能修改 run 专属产物，Asset Finder/manifest 为只读输入。
- **WhenDone**：正常业务扩展文件可暂存、校验并提交；越界读写和受保护修改在**工具层即时拒绝**；失败**不污染正式源码**，测试通过。

## 输入 / 输出契约

- **`FileBackend(run_dir, allowed_paths, *, max_file_bytes)`**（`agent_files.py`）：
  - `read(rel)` / `exists(rel)`：只读 run 授权源码/契约；越界、符号链接逃逸即时 `BAD_REQUEST`；暂存区不经 `read`。
  - `write(rel, data)` / `delete(rel)`：只允许写入 `run-<id>/.staging/` 且路径在 `allowed_paths` 内；
    `..`/绝对/反斜杠/过大 → `BAD_REQUEST`；受保护路径 → `FORBIDDEN`。
  - `build_change_set() -> FileChangeSet`：`FileChange{path, action(create|modify|delete), before_sha256, after_sha256}`。
  - `commit() -> FileChangeSet`：**先整体校验**（路径/受保护/大小），再**原子应用**到 run 源码树；
    应用阶段任一失败 → **回滚**已应用项，源码不被污染；成功后清理暂存。
- **受保护清单**：`asset-lock.json`/`spec.json`/`verification.json`/`coverage.json`/`task-plan.json`/`asset-search.json`/`cost-report.json`/`README.md`；
  认证/安全模板（`.../security/`、`.../config/`、`AuthController`/`AuthService`/`AppUser`/`AppUserMapper` 及 XML）；
  生成项目**固定测试**（`backend/src/test/`、前端 auth/LoginView）。版本化方法仓库/Registry/索引在 run 目录之外，**不可触达**。

## 设计

- **每次读写都校验**：路径先经 `_rel_parts`（拒 `..`/绝对/反斜杠）+ `_safe_join`（`resolve()` 后必须在 root 内，防符号链接逃逸）；
  写入再叠加 `allowed_paths` 与受保护检查；提交前**再校验一遍**。
- **暂存隔离**：写入只落 `run-<id>/.staging/`；提交前源码树不变，失败即回滚（记录 before 内容）。
- **固定验收不可改**：生成项目固定测试与认证模板在工具层直接拒绝修改（“不改写固定验收断言/认证”）。
- **只读输入**：方法仓库/Registry/索引不在此后端的可写范围，Agent 无法修改。

## 风险 / 下一步
