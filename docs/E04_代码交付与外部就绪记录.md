- **Goal**：运行报告把 `code_delivery_status` 与 `external_readiness` 分开，就绪取
  `NOT_REQUIRED / MOCK_ONLY / AWAITING_USER_CONFIG / LIVE_VERIFIED / LIVE_FAILED`。
- **Context**：依赖 E02/E03、R25 历史结果页；技术文档 §3/§7 明确 **Mock 通过不证明 Live 凭据/回调/网络可用**。
- **Constraints**：缺 Live 配置标 `NOT_RUN`/待配置，**不可伪称验证**；只有确认规格要求 Live 为**交付必需**时，
  Live 缺失才影响"完整就绪"；**代码检查与第三方故障分别报告**。
- **WhenDone**：页面能分别呈现代码交付、Mock、Live、缺配置；所有组合状态均有测试；**无真实密钥仍可在 Mock 生成和验收**。

## 输入 / 输出契约

- **`readiness.py`（新，确定性，无模型调用）**：
  - `ExternalService`（脱敏快照）：`service_id/name/mode/required/required_for_live/secret/env_name/
    config_present/mock_status/live_status/reason`。
  - `parse_declared_services(spec.external_requirements, env=…)`：容错解析；**配置就绪只看环境变量是否存在，
    不读取/不暴露其值**。
  - `apply_verification_records(...)` / `declared_services(spec, verification)`：合并 verification 报告的
    逐服务 `mock_status/live_status/reason`。
  - `compute_readiness(services)`：优先级 `无服务 → LIVE_FAILED → 全部必需 Live PASS → 缺必需配置 → MOCK_ONLY`。
    仅 `required and required_for_live` 的服务缺配置才进入 `AWAITING_USER_CONFIG`；已配置但未跑 Live → `MOCK_ONLY`（不标 LIVE_VERIFIED）。
  - `code_delivery_status(run_status, error_code)`：`SUCCEEDED→PASS`；`FAILED→FAIL`，但 **`INFRASTRUCTURE` 单列 `NOT_RUN`**
    （基础设施/第三方故障不算代码失败）；在途 `→NOT_RUN`。
  - `readiness_notice(readiness, services)`：面向用户的中性提示（确定性模板，不改事实/权限/费用/检查状态）。
- **`GET /api/runs/{id}`（`RunDetailView`）** 新增：`code_delivery_status`、`external_readiness`、
  `external_notice`、`external_services[]`（逐服务 Mock/Live/配置/原因）。服务来源 = run 的**冻结规格**
  `external_requirements` + `verification.json` 的逐服务记录；无声明 → `NOT_REQUIRED`。
- **前端 `RunDetailView.vue`**：新增"代码交付与外部服务就绪"卡片——代码交付标签 + 外部就绪标签 +
  逐服务表（服务/模式/Mock/Live/配置/说明）；无服务时显示"无第三方外部服务，无须配置"。

## 设计

- **不新增失败模式**：就绪在**读取时派生**（不改 Run 行、不加迁移）；规格缺失/不可解析时退化为无声明服务。
- **Mock≠Live**：`LIVE_VERIFIED` 仅当**全部交付必需的 Live 服务**都 `PASS`；已配置但未跑 → `MOCK_ONLY`。
- **代码与第三方分离**：`code_delivery_status` 只看本次代码的必需检查；第三方故障经逐服务 `reason`/`live_status` 单独呈现，
  基础设施故障使代码交付状态为 `NOT_RUN` 而非 `FAIL`。
- **无真实密钥可用**：配置缺失只影响 `external_readiness`（`AWAITING_USER_CONFIG`），**不使** Mock 生成/验收失败。

## 费用 / 安全影响

- 费用：无模型调用。
- 安全：仅暴露**布尔/状态**（`config_present` 等），不读取或回显任何配置值；缺配置**不**伪装为验证通过；
  Live 与 Mock 结果分离，避免"Mock 通过 = 可用"的误导。
