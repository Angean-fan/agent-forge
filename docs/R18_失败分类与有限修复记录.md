## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：建立 `classify_failure → coding → 可选 complex_repair → verify` 修复支路，并记录 task/run 的修复次数。
- **Context**：依赖 M17/M18、R15—R17；FR06 限每任务 2 次、全 run 6 次；技术文档第 8 节允许第二次修复升级；默认先 `qwen3-coder-flash`，首修失败或确属复杂才考虑 `qwen3.8-max`。
- **Constraints**：仅**可复现的代码/契约错误**进入修复；基础设施/资产冲突/外部配置**不盲改**；升级由 **Python 明确分类并检查预算**，升级仍消耗该任务第 2 次机会；只传**脱敏**日志、冻结契约与授权源码；**上限即 FAILED**；修复前可查询兼容资产替换（不得无审批改公共方法，替换不省略完整复验）。
- **WhenDone**：注入编译错误时第 1 轮调用 `qwen3-coder-flash` 并复验；构造确定性复杂错误在满足升级条件且额度内才调用 `qwen3.8-max`；超限停止；基础设施不计业务修复次数；全部模型调用有路由/成本日志。

## 输入 / 输出契约

- **`classify_repair_failure(verification, acceptance) -> PASS|CODE|INFRASTRUCTURE`**（`repair.py`，确定性、不调用模型）：
  `NOT_RUN` 状态或错误码 ∈ `{INFRASTRUCTURE, UNKNOWN_CHECK, NO_TESTS}` → `INFRASTRUCTURE`（不修、不计）；其余未通过且可复现 → `CODE`。
- **`choose_repair_role(attempt) -> "coding"|"complex_repair"`**：attempt=0 → `coding`；attempt≥1 且 `complex_repair` 角色已开启 → `complex_repair`，否则仍 `coding`。
- **`RepairLimits(per_task=2, per_run=6)`**（`AGENTFORGE_REPAIR_MAX_PER_TASK`/`_PER_RUN` 可收紧）。
- **`run_repair_loop(...) -> RepairOutcome{classification, attempts, roles, passed, replaced_refs, verification, acceptance}`**：
  分类 →（复用替换 | 受限引擎修复+校验+原子提交）→ 复验；`per_task`/`per_run` 双上限，达限即停。
- **`replacement_candidate(search, spec, methods_root)`**：有兼容、已验证且声明所需验收的方法单元时，优先**替换**失败代码（复用装配，不调用 Agent）。
- **生成图**：`verify → repair → check_coverage`；`GenerationContext.repair_engine_factory` **默认 None（不修复）**；修复任务 `RunTask(task_id="repair:verify").attempt` 记录次数，`repair` 事件记录分类/角色/是否通过。
- **coding 角色**由 `AGENTFORGE_CODING_ENABLED`、**complex_repair 角色**由 `AGENTFORGE_COMPLEX_REPAIR_ENABLED` 显式开启（默认关闭）。

## 设计

- **分类先行、确定性**：失败先分类；基础设施/NOT_RUN 一律**不盲改、不计业务次数**（避免把环境故障当业务 bug 反复烧钱）。
- **升级由 Python 决策**：仅第 2 次尝试、且升级角色已开启时才切 `complex_repair`；升级消耗该任务第 2 次机会——**不自动无限升级**。
- **双上限**：`per_task=2`（RunTask.attempt）+ `per_run=6`（跨修复任务累计）；达上限即停，由 `package_or_fail` 落 FAILED。
- **上下文最小且冻结**：修复只传**脱敏**失败信号（runner 已脱敏）+ 冻结契约 + 授权文件；提示明确禁止改模板原件/公共方法、改固定测试、绕过或删除失败检查。
- **替换优先于重写**：修复前先查兼容已验证资产可替换失败代码，能复用则复用、不调用 Agent；替换同样走完整复验。
- **路由/成本留痕**：修复经 R16 `LedgerChatModel`，逐次请求继承 run/task/call_id 入账；两种角色均由网关静态路由（`qwen3-coder-flash` / `qwen3.8-max`）。

## 风险 / 下一步

- **修复授权面有限**：修复 allowed_paths 为契约实体的 **service/controller 层**；真实编译错误若落在更广目录（如 pack 渲染的 entity/mapper）需后续按主线扩展有限集合，当前不开放任意目录。
- **升级判据为「首修失败即视为复杂」**：满足「首修失败才考虑 Max」；未来可加入更细的复杂度签名（如多检查失败）作为附加条件。
- **替换映射为验收级**：`replacement_candidate` 以「兼容方法声明了所需验收」判定可替换，属保守近似；更精确的失败代码↔方法映射留待后续。
