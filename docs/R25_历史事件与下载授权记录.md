## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：补齐历史列表、规格版本/run 状态、递增事件分页、阶段成本与失败产物下载。
- **Context**：依赖 MVP M27、R22—R24；FR07/FR08 要求取消、状态、失败原因与历史；以 `after_sequence` 增量轮询。
- **Constraints**：下载严格校验 **owner 与 artifact_id**；失败包显著标“未通过验证”，不虚构完成百分比；普通状态/失败码用**确定性模板**（仅必要用户解释才走 DeepSeek 并计账）；**不把 Qwen 工具日志/隐藏思考**给前端；日志脱敏并按保留周期清理。
- **WhenDone**：查自己的历史规格、失败详情与重入状态；跨用户不可查看/下载；成功/失败包状态与验证报告一致；可查询已采用方法版本/拒绝原因/未覆盖规则；下载遵守 owner 与脱敏。

## 输入 / 输出契约

- **`runs.list_project_runs(db, project_id, *, limit=100)`**：项目运行历史（按 id 倒序）。
- **`runs.find_artifact_by_id(db, run_id, artifact_id)`**：按 run + artifact 双重定位（拒绝跨 run）。
- **`GET /api/projects/{project_id}/runs`** → `RunHistoryData{project_id, items:[RunView]}`（归属校验）。
- **`GET /api/runs/{run_id}/cost`** → `build_cost_report`（访谈期 / run 级 / 各 task / by_model）；归属校验。
- **`GET /api/runs/{run_id}/artifacts/{artifact_id}`** → 下载；严格校验归属与 artifact 属于该 run；`X-Artifact-Verified` 标注。
- **`RunView`** + `spec_version`、`failure`（确定性模板）。
- **`RunDetailView`** + `spec_version`、`failure`、`package{available, artifact_id, verified, label, notice}`（成功/失败包一致标注）。
- **`_failure_message(error_code)`**：确定性错误码→用户文案映射（不调用模型）。

## 设计

- **归属与 artifact 双重校验**：历史与成本经 `require_project_owner`；下载经 `require_run_owner` + `find_artifact_by_id`（artifact 必须属于该 run），跨用户 403、跨 run 404。
- **失败用确定性模板**：`error_code` → 固定文案；需要用户解释时才另走 DeepSeek（本步不启用），前端**从不**收到 Qwen 工具日志/隐藏思考（事件 payload 均为平台自身写入的阶段名/哈希/错误码）。
- **交付包一致标注**：`package.verified` 取自 `verification.json`（缺失回退产物 `verified`），失败包含显著“未验证”提示，不显示虚构完成百分比。
- **阶段成本复用 R20 分层报表**：访谈期 / run 级 / 各 task / by_model，只读且归属校验。
- **增量事件**：沿用 `after_sequence`（R25 只补归属列表与成本/下载，事件分页语义不变）。
