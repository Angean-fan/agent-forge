## 统一 manifest schema（`AssetManifest`，契约字段全部保留）

必需：`id / version / kind / compatible_profiles / requires / provides / conflicts /
parameter_schema / extension_points / owned_paths / checks / checksum / license`；
可选：`provided_capabilities`（模板能力）、`renders` / `dependencies`（能力包渲染与依赖注入）。
`extra="forbid"` 保证字段集合稳定。

- **模板 `base-template@demo-0.1`**：`provided_capabilities` = [auth, jwt-security, exception-handling, health, flyway-migration, router, api-client, login-page, base-layout]；`extension_points` = pom 依赖注入点 + 前端 api/views/types/router-modules；`provides` 留空（能力经 `provided_capabilities` 登记，避免重复注入认证）。
- **两个能力包**：新增 `extension_points: []` 与 `checksum`。

## 注册表（只读本地）

`AssetRegistry(roots)` 扫描各根目录及其一级子目录的 `manifest.json`，以 `(kind, id, version)` 建索引：

- `get(kind, id, version)` → 缺失抛 **`ASSET_NOT_FOUND`**；
- `verify_checksum(kind, id, version)` → 内容变更抛 **`ASSET_CHECKSUM_MISMATCH`**；
- `resolve(kind, id, version, profile)` → Profile 不兼容抛 **`ASSET_INCOMPATIBLE`**；
- `all()` 列出全部资产。

**checksum 定义**：对资产目录（排除 `manifest.json` 自身与 `node_modules/target/dist/build/__pycache__`）内每个文件的「相对路径 + 文件内容 SHA-256」排序后取 SHA-256；与 git 状态可复现，且不受 mtime 影响。CLI：`python -m agentforge_platform.asset_registry [--update]`（`--update` 回填各 manifest 的 checksum）。

`capability_packs.py` 改为统一使用 `AssetManifest`（原专用 `CapabilityPackManifest` 移除），渲染路径不变。

## 剩余风险 / 阻塞

- checksum 覆盖的是 git 跟踪的源文件级内容；CI/发布流程可据此断言资产未被篡改（M14 锁清单将进一步消费）。
- 无阻塞。
