## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：实现可配置的全 run 模型次数、单次输出、模型等待、Agent 工具循环及运行总时限。
- **Context**：依赖 R20、R16—R18；技术文档建议上限 30 次调用 / 12,000 token 输出 / 120 秒等待 / 40 次工具操作 / 总 20 分钟。
- **Constraints**：DeepSeek 非思考/思考及 Qwen 规划/编码/升级调用**全部经同一调用次数/预算守卫**；AI 解释请求同样计费计数；限制由网关与任务控制器执行，**未知在途账单不自动重发**；运行超时触发 Runner 清理；访谈发生在 run 前须有**独立且可追溯**的项目级限额。
- **WhenDone**：每一种限额有**独立边界测试**；达上限的模型调用或工具写入被拒；报错分类与成本记录完整。

## 输入 / 输出契约

- **`RuntimeLimits` / `runtime_limits()`**（`limits.py`）：`max_model_calls_per_run=30`、`max_output_tokens_per_call=12000`、`model_timeout_seconds=120`、`max_tool_ops=40`、`run_timeout_seconds=1200`；`agent_recursion_limit = 2*max_tool_ops+5`。环境变量：`AGENTFORGE_MAX_MODEL_CALLS_PER_RUN`/`_MAX_OUTPUT_TOKENS`/`_MODEL_TIMEOUT_SECONDS`/`_MAX_TOOL_OPS`/`_RUN_TIMEOUT_SECONDS`。
- **`model_gateway.reserve`**：**所有角色**生成期调用统一检查——单次 `max_output_tokens` 超上限 → `OUTPUT_LIMIT_EXCEEDED(422)`；全 run 调用次数（`status != NOT_SENT` 计数）达上限 → `CALL_LIMIT_EXCEEDED(429)`。`run_id` 为空的访谈/草稿调用走**独立** `_enforce_draft_limits`。
- **`clients.DeepSeekClient.timeout_seconds`**：模型等待时限（默认 120s，可配）。
- **`PatchEngine.run(recursion_limit=None)`**：默认取 `agent_recursion_limit`；工具循环超限（`GraphRecursionError`）→ `TOOL_LIMIT_EXCEEDED(429)`，不产生半成品提交。
- **`run_generation`**：设置单调时钟截止 `deadline_monotonic = now + run_timeout_seconds`；每个图节点入口 `_check_deadline` → 超时 `GenerationError("RUN_TIMEOUT")`；失败前**尽力**调用 `runner.cleanup(run_dir)`（客户端可选实现）。
- **错误码**：`CALL_LIMIT_EXCEEDED` / `OUTPUT_LIMIT_EXCEEDED` / `TOOL_LIMIT_EXCEEDED` / `RUN_TIMEOUT`。

## 设计

- **统一守卫在网关**：调用次数与输出上限在 `reserve` 一处判定，DeepSeek/Qwen 各角色、Agent 内层循环与升级修复**共用同一路径**，无旁路。
- **访谈期独立限额**：`run_id` 为空走既有 draft/project 级限额（可追溯），与 run 级限额互不影响，避免生成前请求挤占 run 预算/次数。
- **工具循环硬上限**：以 LangGraph `recursion_limit`（由 `max_tool_ops` 派生）中止失控循环，超限即抛错、**不提交**暂存变更。
- **运行总时限在节点边界**：不依赖线程强杀；超时以 `RUN_TIMEOUT` 落 FAILED 并尽力清理 Runner，避免长跑占用受控主机。
- **不自动重发**：未知在途调用保持 UNKNOWN，不因超时/失败自动重发（避免重复计费）。

## 风险 / 下一步

- **运行时限为节点粒度**：单个节点内的长阻塞（如一次超长 Runner 调用）不在节点边界内拦截；Runner 侧仍应设置自身超时并清理容器。
- **`runner.cleanup` 为可选协议**：当前 `HttpRunnerClient` 未实现 `cleanup`；生产接入受控 Runner 的清理端点后方可端到端回收。
- **次数上限按 run 计数**：与账本行一致（含 Agent 内层逐次请求）；访谈期请求不计入 run 次数（走独立限额）。
- **下一步 R22**：取消 run 与 Runner 资源回收（幂等 `POST /api/runs/{id}/cancel`，阻止新分发、尽力停止在途，保留已花费/在途预留，UI 说明可能费用）。
