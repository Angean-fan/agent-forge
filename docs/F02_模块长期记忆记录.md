## 4. 输入 / 输出契约

- **索引键**：`(project_id, module_id, spec_hash) + contract_revision`；每条决策关联
  `task_id/commit_hash/verification_ref/revision`。
- **存储**：`<root>/<project_id>/<module_id>.json`（`memory.json` 约定；独立 `schema_version="0.1"`）。
- **读取**：`read(...) -> MemoryView{status(CURRENT|REBUILD_REQUIRED), entries(仅兼容), notice}`。

## 5. 关键设计

- **可信更新**：`record(verified=True, committed=True)` 才落盘；模型无法直接覆盖存储入口。
- **隔离**：按模块分文件；`project_id/module_id` 经安全字符校验（拒绝穿越/绝对路径）。
- **失效**：`spec_hash` 或 `contract_revision` 变化 → 相关条目 `REBUILD_REQUIRED`，**旧记忆不被篡改**，
  仅提示重建（不生成隐式业务规则）。
- **幂等与原子**：同键同值同证据不双写、不递增修订；写临时文件后 `os.replace` 原子替换。
- **回退**：`rollback(to_revision)` 丢弃晚于目标修订的条目，记忆指针随代码版本回退、不悬空。
- **边界**：不保存秘密（`scan_for_secrets` 命中即拒）、原始对话或隐含推理；限制条目数与摘要体积。
- **不引入**：向量库、云存储、额外模型。
