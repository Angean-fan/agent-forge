## 模型（技术文档第 4 节）

- `project(id, owner_id, name, active_spec_id, created_at)`；`owner_id` 建索引（M04 引入账号后保证归属检查）。
- `spec_version(id, project_id, version, body_json, hash, confirmed_at)`；`UNIQUE(project_id, version)`。
- `spec_version.project_id → project.id`（`ON DELETE CASCADE`）。
- `project.active_spec_id` 指向 `spec_version.id`，因与 `project_id` 形成循环引用，**DB 层不加外键**，由应用层在 M07 维护；模型仅保留字段。

## 设计要点

1. **WAL 与短事务**：`make_engine` 在 `connect` 事件里设置 `journal_mode=WAL`、`foreign_keys=ON`、`synchronous=NORMAL`、`busy_timeout=5000`；`session_scope` 成功提交、异常回滚、随后关闭，保持短事务。
2. **平台/生成项目隔离**：本层仅面向平台 SQLite；生成项目使用独立 MySQL，不复用该引擎。
3. **不塞大对象**：`spec_version.body_json` 仅存结构化规格 JSON；不存生成源码或运行日志。
4. **迁移机制**：Alembic；`env.py` 连接串优先取显式设置值，否则回落 `AGENTFORGE_DATABASE_URL`；启用 `render_as_batch` 以支持后续 SQLite 变更。初始迁移 `0001` 手写以保证确定性。

### 唯一约束的口径说明

M03 WhenDone 的"项目与规格版本唯一约束"，按技术文档第 4 节 `spec_version` 的"project 与 version 唯一"实现为 **`UNIQUE(project_id, version)`**；`project` 侧保留主键唯一。若需额外约束（如 `(owner_id, name)` 唯一），请确认后再加，本步未擅自新增。
