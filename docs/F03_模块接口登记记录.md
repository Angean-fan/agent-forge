## 2. Goal 与判定

**Goal：** 为**当前生成项目运行/版本**的已实现接口建立独立发现层：模块发布公共契约，其他模块按
`capability_id` 只读查询复用，**不读提供者私有源码/记忆**。

**结论：** 状态由**证据**决定（自报无效）；`DRAFT` 仅规划可用、不可当可调用能力；`JAVA_METHOD`/`HTTP` 分离；
冲突、模糊签名、破坏性升级、越权修改一律阻塞；持久化可重放；不触碰 Method Unit/FTS5/asset-lock。

## 4. 输入 / 输出契约

- **能力字段**：`capability_id`（`module.name`）、`owner_module_id`、`interface_kind`（`JAVA_METHOD|HTTP`）、
  `symbol`/`signature`/`args_schema_ref`/`returns_schema_ref`/`errors`/`auth_constraints`/`version`/
  `status`/`verification_ref`（HTTP 另有 `http_method`/`http_path`）。
- **证据**（程序提供）：`source_committed && contract_consistent && runner_verified && verification_ref`。
- **存储**：`<run>/interfaces.json`，独立 `schema_version="0.1"`。

## 5. 关键设计

- **证据决定状态**：`register_capability` 依据 `CapabilityEvidence` 置 `VERIFIED`/`DRAFT`，**忽略**入参自报的
  `status`（模型自报无效）。
- **消费者只读**：`lookup` 默认只返回 `VERIFIED`；`include_draft=True` 仅供规划。
- **类型分离**：`JAVA_METHOD` 必须 `类.方法` 符号，`HTTP` 必须方法+路径；**URL 不得混充 Java 调用**。
- **阻塞项**：模糊签名（`?`/`*`/`todo`/`unknown`…）、能力 ID 格式非法、同 id+version 冲突、多个 VERIFIED、
  非所有者覆盖、破坏性升级（签名/DTO/错误/权限/所有者变化或版本未递增）。
- **破坏性升级**：默认拒绝（`INTERFACE_CONFLICT`）；`allow_breaking=True` 时旧版标 `DEPRECATED`（触发依赖迁移）。
- **隔离**：只暴露公共契约字段；不读提供者实现；不引用 Method Unit/FTS5/asset-lock/resolver。
