## 输入 / 输出契约

- **输入**：已校验的 `SoftwareSpecification`（新增可选字段 `pages: list[BusinessPage]`，`BusinessPage = {name, entity?, path?}`）。
- **输出**：
  - `scope_issues(spec)` → 业务实体/角色/页面**数量**超限 → 确认入口 `422 UNSUPPORTED_SCOPE`（附缩减建议）。

  - `is_legacy_task_spec(spec)` → 生成入口：非旧单实体 Task → `422 SCOPE_CAPABILITY_NOT_READY`；旧 Task 照旧。

## 设计

- **规则分层**：`scope_issues` 只判**通用数量**（实体 ≤3、角色 ≤2、页面 ≤8）；字段名安全/类型白名单与权限动作属**通用有效性**，随所有实体在 `confirmation_issues` 校验；固定 `Task` 字段、可搜索字符串、`ADMIN/MEMBER` 角色等**仅旧单实体 Task**。
- **确认**：`confirm_draft` 先判范围（`UNSUPPORTED_SCOPE`），再判就绪（`SPEC_NOT_READY`）；契约与固定能力包编译**仅在旧 Task 路径**执行——合法多实体候选允许确认、不在确认期编译。
- **生成门禁**：`start_run` 载入 `active_spec_id` 指向的已确认规格（行不存在时放行，兼容既有测试/历史流程）：范围超限 → `UNSUPPORTED_SCOPE`；非旧 Task → `SCOPE_CAPABILITY_NOT_READY`，**不创建 run**。R10 后续以同一错误码解除门禁。
- **hash 影响**：新增可选字段使 `content_hash` 变化，故 `schemas/task-management.contract.json` 的 `spec_hash/contract_hash` 随之更新（`diff` 确认其余字段完全一致）；已确认 spec 行的**存储 hash 不被改写**。
