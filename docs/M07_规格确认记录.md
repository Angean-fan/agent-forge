## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：增加 `GET/PUT /api/projects/{id}/spec` 和 `POST /api/projects/{id}/confirm`，实现规格的编辑、确认与不可变冻结。
- **Context**：依赖 M03—M06；需求文档 FR03 要求确认版本与 hash；技术文档第 5 节要求乐观锁、冲突 409；M20 运行入口只接收冻结版本。

## 语义与状态

- 每个项目最多一个**草稿**（`spec_version.confirmed_at IS NULL`）；确认即设 `confirmed_at` 并把 `project.active_spec_id` 指向该版本。
- `PUT`（乐观锁，body 带 `version`）：
  - `version != 当前最高版本` → `409 SPEC_CONFLICT`；
  - 无规格且 `version=0` → 新建草稿 `version=1`；
  - 最新为草稿 → **原地编辑**；
  - 最新已确认 → **新建下一版本草稿**（不原地修改已确认行）。
- `POST /confirm`（body 带 `version`）：
  - 无草稿（无行或最新已确认）→ `404 SPEC_NOT_FOUND`；
  - 版本不匹配 → `409 SPEC_CONFLICT`；
  - `confirmation_issues` 非空（缺实体/权限/规则、非法 Profile、多实体、关键 pending）→ `422 SPEC_NOT_READY`，message 列出问题；
  - 否则冻结：写 `confirmed_at`，返回 `spec_id/version/hash/confirmed_at`。
- `GET /spec`：返回最新版本（草稿优先），含 `version/confirmed/confirmed_at/hash/spec/pending/issues`；无任何规格 → `404 SPEC_NOT_FOUND`。
- **hash 稳定性**：`SHA-256(canonical_json)`，其中 `canonical_json = json.dumps(model_dump(mode="json"), sort_keys=True, separators=(",",":"), ensure_ascii=False)`；键顺序无关，同内容恒等。
