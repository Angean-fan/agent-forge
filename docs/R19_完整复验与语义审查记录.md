- **Goal**：打包前执行完整必需验证；可选由 **Qwen3.7 Plus** 对照冻结业务规则做**最多一轮**技术语义审查，问题须转换为可验证的具体修复任务。

- **Constraints**：审查只接收**冻结 spec、契约、代码与固定验收结果**，不重新解释 DeepSeek 原对话；不因 Qwen 自评绕过失败测试；**如代码变化必须重新完整验收**；审查不得改冻结规格与固定测试；需面向用户解释时由 DeepSeek 在脱敏事实之上转述。
- **WhenDone**：失败用例无法走到 SUCCEEDED；修复后所有必需项确实重新 PASS；报告保留首次失败及最终复验记录；报告保存索引版本、采用/拒绝方法、装配及 Agent 修改的来源链；方法命中且构建成功但固定业务 HTTP 失败时不得标为已覆盖。

  必需检查 `static_manifest/backend_test/backend_build/frontend_build` 缺项即**不可能通过**；缺项名写入报告。

  冻结上下文（spec/契约/固定验收结果/授权代码片段），**不含对话历史**。
- **`ReviewFinding`（pydantic，extra=forbid）** + **`_ReviewOutput`**：审查结构化输出；**`findings_to_tasks(findings, contract)`** 转为可验证修复任务（`task_id="review:<i>"`、有限 `allowed_paths`、`acceptance_ids`）。
- **`run_semantic_review(db, *, project_id, run_id, client, context, max_rounds=1) -> ReviewResult`**：
  经 **`technical_planning`（qwen3.7-plus）** 结构化调用（`json_mode`）；`finish_reason != stop` 或 schema 非法 → 记 `REVIEW_INCOMPLETE/REVIEW_INVALID`，**不伪装成功**。

- **报告**：`package_or_fail` 产出 `report.json`：`verified`、`missing_required_checks`、`first_failure`、`final_verification`、`provenance`（lock/manifest hash、index_revision、采用方法、selected/rejected、`agent_modifications`：gap 决策 + 修复记录）、`semantic_review`。

## 设计

- **完整复验是前提、非装饰**：`verification_passed` 本就要求必需检查全部 PASS，缺项必然判失败；R19 额外把**缺项名**写入 `verify` 事件与 `report.json`，令"未完整复验"可追溯（不改变 M24「失败也产出未验证包」的语义）。
- **审查不改结论**：`review` 只读冻结上下文、只**产出问题**并转成 PENDING 修复任务；确定性 `verification/acceptance` 不被模型评价覆盖（`package_or_fail` 仍以 `verification_passed` 决定终态）。
- **代码变化必须重新完整验收**：审查本身不改代码；若修复支路（R18）落代码变更，其内部会重新 `verify+accept`，最终报告取自**最后一次**复验。
- **报告来源链**：`asset-search.json`（index_revision/selected/rejected）+ `report.json.provenance`（采用方法、装配 manifest/lock hash、Agent 修改：gap 决策与修复角色/次数）。
- **覆盖诚实**：方法命中、构建成功但固定验收 FAIL → `acceptance_passed=False` → `covered` 置空、`report.verified=False`、run FAILED。
