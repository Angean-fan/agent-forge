## 接口

- `POST /api/projects`（需登录 + CSRF）`{name, requirement}` → `201`，返回项目详情。
- `GET /api/projects`（需登录）→ 当前用户项目列表（按 id 倒序）。
- `GET /api/projects/{id}`（需登录 + 归属）→ 项目详情（含原始需求文本）。
- 长度：名称经 `strip` 后 1–60 字符；需求经 `strip` 后 20–5000 字符；越界 → `422 VALIDATION_ERROR`。
- 未登录 → `401 UNAUTHORIZED`；跨用户详情 → `403 FORBIDDEN`；缺失 → `404 NOT_FOUND`。

## 设计要点

1. **原始需求文本落库**：技术文档第 4 节将 `project` 字段列为“主要字段”（非穷尽），本步按 M05 要求新增 `requirement_text TEXT NOT NULL` 列（迁移 `0003`），用于 M06 生成规格草稿、M22 结构化提取。
2. **长度校验**：用 Pydantic `StringConstraints(strip_whitespace=True, min_length, max_length)`，先去空白再判定，避免纯空白通过。
3. **仅创建/读取**：创建走 `flush + refresh` 取回服务端生成的 `created_at`，不触发生成链路、不调用模型。
4. **归属隔离**：列表按 `owner_id` 过滤；详情复用 M04 的 `require_project_owner`。
5. **越界不静默裁剪**：超范围长度直接 422，不做截断。
