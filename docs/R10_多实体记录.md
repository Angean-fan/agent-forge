日期：2026-10-12
状态：完成（契约多实体 + 外键、能力包逐实体渲染、装配、门禁解除；构建认证；真实 HTTP 记 NOT_RUN）
前置：R09（`6633aa0`）；迭代文档 D2 的 R10。

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：把装配器从单 `Task` 扩展为有明确**一对多/多对一**关系的 2—3 业务实体装配；每关系/辅助逻辑先查已审核资产，未覆盖才按确定性路径实现。
  （本次确认：**仅确定性一对多/多对一**；**扩展既有单实体包（逐实体参数化渲染）**。）
- **Context**：依赖 M06/M10—M12/M15、R01/R06；原 `contract.py` 有 `MVP_ENTITY_LIMIT=1` 且只编译 `entities[0]`；技术文档第 6 节要求“数据库、DTO、REST 契约先冻结，再装配”。
- **Constraints**：先扩展确定性契约编译，再扩展能力包/装配器/Runner；**每实体/关系生成独立表、DTO、REST、权限及外键**，不得只放开校验却丢弃第二实体；命名冲突（表/路由/DTO/列）在写文件前拒绝；不自动允许模型新增第 4 实体；**R01 门禁仅在完整链路通过后解除**。
- **WhenDone**：一套 2—3 实体规格生成含全部实体与正确外键的 migration、服务、页面及权限/HTTP 验收；缺一实体即失败；重复渲染无漂移；旧单 Task 生成与验收 PASS。

## 输入 / 输出契约

- **契约编译** `compile_from_spec`：支持 `1..MAX_BUSINESS_ENTITIES(3)` 实体；`relations` 为 `[{child,parent,kind∈{many-to-one,one-to-many},required?}]`，
  统一解析为**子实体持有父外键** `<parent_snake>_id`（可空，`required=true` 则非空）；实体按**父先子后**拓扑序输出；未知实体/自关联/环/重复表名/路由冲突/字段列冲突 → `CONTRACT_UNSUPPORTED|CONTRACT_CONFLICT`。
  **单实体输出与 R10 前逐字节一致**（契约夹具 `task-management.contract.json` 仍匹配）。
- **能力包** `build_params(contract, entity_name=None)`：按实体渲染；`entity_name=None` 仍要求恰好单实体（MVP 语义不变）。
  新增参数 `migration_version(=2+实体序)`、`foreign_keys_sql`、`fk_java_names`、`search_field_name`。
  `render_pack_files(pack_dir, contract, *, entity_name=None)` 逐实体渲染。
- **装配器**：对每个能力包**逐实体渲染**；**同一实体内重复目标仍拒绝**；**跨实体同路径内容一致则去重**（如 `PageResult.java`），不一致即冲突。
- **门禁解除**：`POST /projects/{id}/runs` 不再返回 `SCOPE_CAPABILITY_NOT_READY`（仅保留通用 `UNSUPPORTED_SCOPE`）；`POST /confirm` 现在对**每个业务实体**逐一验证契约与能力包可渲染。

## 设计

- **版本策略（已确认）**：为不原地覆盖已发布资产，多实体能力以**新版本 0.2.0**发布，多组合共享（backend/frontend 各一套兼容两组合）；
  **旧版本继续发布** → 旧锁仍可 `verify_lock_hash` + 按旧 ID/version/checksum 重放；R06A 冻结基线夹具不受影响。
  **代价**：`resolve_assets` 对四组合选到 0.2.0 → 四份 `asset-lock` 样例更新（`resolve==样例` 断言随之更新）。
- **外键与迁移顺序**：契约按父先子后输出 → 迁移 `V2__create_activity.sql` + `V3__create_enrollment.sql`（含 `FOREIGN KEY (activity_id) REFERENCES activity(id)`）。
- **逐实体渲染**：能力包（entity/mapper/service/controller/dto/vo/migration/test…）按实体渲染；跨实体共享文件按内容去重。
- **顺带修复两个旧模板隐性缺陷**（多词列才暴露）：生成测试的 payload 用 **snake 字段名**比较搜索列（原用 camel）；外键列在测试 payload 中跳过（默认可空）。
