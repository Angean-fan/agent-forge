## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：实现幂等 `POST /api/runs/{id}/cancel`，设置 `cancel_requested`、阻止新任务分发并尽力停止在途工作。
- **Context**：依赖 M19/M20、R21；取消不保证撤回 Provider 已处理调用。
- **Constraints**：取消后不能再发新模型请求/新 Runner 检查；对已花费或在途预留**如实保留**；**不能仅把 UI 改成 CANCELLED 而让后端继续执行**。
- **WhenDone**：连点取消不重复执行；模拟慢任务可停止后续派发并释放隔离容器；账本保留在途/已确认额度；界面说明可能发生的费用。

## 输入 / 输出契约

- **`model.R.run.cancel_requested`（迁移 `0013`）**：布尔标志，幂等置位。
- **`request_cancel(db, run)`**（`runs.py`）：终态（SUCCEEDED/FAILED/CANCELLED）→ no-op；已请求 → no-op（**连点不重复**）；`QUEUED` → 直接 `CANCELLED`；在途 → 置标志（由 worker 落终态）并写一次 `cancel_requested` 事件。
- **状态机**：新增 `RunStatus.CANCELLED` 与 `TERMINAL_STATUSES`；`QUEUED/PLANNING/GENERATING/VERIFYING → CANCELLED` 允许，`CANCELLED: set()`。
- **`claim_run`**：`where cancel_requested is false` → **不再派发**已请求取消的 run。
- **生成图**：`_check_cancel` 在**每个节点入口**观察标志 → `GenerationError("RUN_CANCELLED")`；`run_generation` 领取前检查（避免派发）、异常路径把非终态落 `CANCELLED` 并**尽力** `runner.cleanup(run_dir)`。
- **API**：`POST /api/runs/{run_id}/cancel`（归属 + CSRF）→ 幂等返回 `RunView`；`RunView.cancel_requested` 与 `RunDetailView.cancellation{requested, notice}`（费用说明）。
- **前端**：运行页在非终态显示“取消运行”按钮；取消后显示“运行已取消/已请求取消”与**费用提示**；`CANCELLED` 标签为 info。

## 设计

- **幂等且不重复执行**：`request_cancel` 对终态/已请求直接返回；连点只写一次事件；`QUEUED` 直接落 `CANCELLED` 且 `claim_run` 跳过，杜绝“UI 取消但后端照跑”。
- **在途取消在节点边界**：与 R21 超时同一位点观察，取消 → `RUN_CANCELLED` → 落 `CANCELLED` 并触发 `runner.cleanup`（尽力释放隔离容器）；不发新模型请求、不再派发后续任务。
- **账本保留**：取消**不删除/不清零**任何 `ModelCall`（在途预留与已结算额度如实保留）。
- **费用提示**：API 返回 `cancellation.notice`，前端在取消/已取消时展示“取消不撤回已处理调用”的说明。

## 风险 / 下一步

- **在途取消为尽力而为**：单个长阻塞内不立即中断；Provider 已处理的调用无法撤回（费用仍计），与文档一致。
- **`runner.cleanup` 为可选协议**：`HttpRunnerClient` 尚未实现；接入受控 Runner 的清理端点后方可端到端回收容器。
