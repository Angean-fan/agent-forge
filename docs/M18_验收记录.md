## 验收编排（`POST /accept`）

隔离网络内，每次 run：
1. **镜像对账**：从 `<run>/compose.yaml` 取 MySQL `reference@digest`，与 `<run>/asset-lock.json` 的 `mysql_image` 比较（`digest_reconciled`）；启动后 `docker image inspect` 复核实际解析 digest。
2. **构建后端 jar**：`mvn -B -DskipTests package`（依赖经 `container_network`）→ `backend/target/backend-0.1.0.jar`。
3. **启动 MySQL**（锁 digest）+ 就绪探测（**TCP + 指定用户可连**，避免 init 阶段误判）。
4. **启动后端**（隔离参数 + 仅发布 8080 到宿主回环；Flyway 迁移建表）。
5. **播种演示 MEMBER 用户**（bcrypt）至隔离库。
6. **固定 HTTP 用例**（平台固定、按契约权限自适应）：`login_admin/login_member/create_task/list_total/get_own/update_own/search/pagination_page_zero/pagination_size_too_large/cross_user_denied/delete_own`；**契约含受限角色时**追加 `role_denied`。结束清理容器与网络。

`contract.json`（M15 起随产物交付）用于判定角色用例适用性；装配器**不修改**断言。

## 剩余风险 / 偏差（如实记录）

- **依赖来源**：与 M17 同，构建容器的 Maven 依赖经 `RUNNER_CONTAINER_NETWORK=bridge` 临时放行（无受控代理/预热缓存）；默认 `none`。
- **MySQL 容器隔离弱于生成代码容器**：MySQL 为受信镜像（锁 digest），仅限网络/临时盘；**生成后端**才套用 `--read-only`/`cap-drop`/`no-new-privileges` 等强隔离。
- **`role_denied` 仅在契约存在受限角色时纳入**（普通 Task 两角色同权，无此用例）。
- MySQL/后端端口仅发布到宿主 **回环**；每 run 独立网络与随机端口。
- 执行镜像未推送 registry；基础镜像仍为可变 tag。
