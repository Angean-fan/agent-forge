## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：用 **DeepSeek V4.1 Flash（`user_interaction`）** 整理面向用户的最终需求摘要（复杂汇总可用经验证的 `high`）；
  经用户确认后由程序冻结**功能、排除项、业务规则及独立验收场景**；变更后创建新 spec 版本。
- **Context**：依赖 R01—R05 与 MVP M07；需求文档 FR03、第 8 节要求验收断言与规格一同冻结，编码 Agent 无权修改。
- **Constraints**：`pending` 核心项未清零不得确认；复杂汇总若选用 `enabled + high` 须**复用 R03 已验证的参数/账本路径**，
  不支持时不得声称已使用 `high`；DeepSeek 只起草/解释、**不能替用户同意**；技术规划模型不得在冻结后重解释原对话或改业务规则；
  生成中的 spec 不允许原地编辑，**冻结哈希进入 run**。
- **WhenDone**：可查看规格版本差异；旧 run 指向旧 spec 的 hash；人为篡改冻结的验收断言会在检查中被拒绝。

## 输入 / 输出契约

- **`POST /api/projects/{id}/summary`** body `{version, draft_revision}`
  → `SpecSummaryView{spec_id, version, draft_revision, summary, thinking_mode, reasoning_effort}`。
  仅作用于**未冻结草稿**（已冻结 → 409），存在核心 `pending` → 422 且**不调用模型**；
  返回**实际使用**的思考模式（未验证强度不下发，绝不谎称 `high`）。DeepSeek 只改 `summary` 文本，不改任何 `source`。
- **`GET /api/projects/{id}/spec/diff?from_version=&to_version=`**
  → `{from:{version,hash}, to:{version,hash}, changes:[{section,key,kind(added|removed|changed),before,after}]}`；
  section ∈ {goal, actors, entities, pages, permissions, business_rules, acceptance_cases, constraints, exclusions}。
  版本不存在 → 404 `SPEC_NOT_FOUND`。
- **`POST /api/projects/{id}/runs`**：提交前校验 active spec **冻结完整性**（重算 hash + 验收场景结构），
  篡改 → 409 `SPEC_TAMPERED`；通过则把 `spec_version.hash` 记入 `run.spec_hash`。
- **`GET /api/runs/{id}` / 提交响应** 新增 `spec_hash`：旧 run（R06 前）无记录时按 `spec_id` 回退解析。

## 设计

- **冻结即“功能+排除项+业务规则+独立验收场景”**：这些字段本就在 `spec_version.body_json` 中，确认时随 `confirmed_at` +
  规范化 hash 一起冻结；R06 增加**共享完整性校验** `require_frozen_spec`：重算 `content_hash` 必须等于冻结值，
  且验收场景/业务规则的 `id` 非空、不重复。篡改任一断言 → `SPEC_TAMPERED`（409，可追溯）。
- **run 绑定旧 hash**：提交时把冻结 hash 写入 `run.spec_hash`，**编辑已确认规格会新建版本**（M07 语义），
  因此旧 run 永远指向旧 spec 的 hash，不随新版本漂移；生成期再校验 `row.hash == run.spec_hash`，
  运行创建后的篡改在**生成检查**被拒（`SPEC_TAMPERED`）。
- **最终摘要的思考模式由 Python 决定**（`select_summary_thinking`）：复杂度 = 多实体，或业务规则+验收场景 ≥6，
  或业务页面 ≥4。复杂 → 若 `high` 在 `AGENTFORGE_VERIFIED_REASONING_EFFORTS` 则 `enabled+high`，否则降级 `low`（若已验证）；
  简单 → `disabled`。强度经 R03 已验证路径下发并入账；响应回传**实际**模式，避免“谎称 high”。
- **不替用户确认**：摘要只写 `summary` 文本；`pending` 非零时 422 且不调用模型；`source` 全流程不变。
