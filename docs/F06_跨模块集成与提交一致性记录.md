## 2. Goal 与判定

**Goal：** 确保"模块各自成功"≠"项目整体成功"：跨模块契约检查 + 状态提交/发布的可恢复一致性。

**结论：** 静态一致性门禁（`integration_ok`：**任一冲突 → 整个 run 不通过**）；可恢复提交状态机
（对账检出不一致、可回滚）；验证绑定 `contract_revision + source_hash + verification_ref`，源码/契约变化即失效。

## 4. 输入 / 输出契约

- **输入**：`ModuleRegistry`（F01）、`InterfaceRegistry`（F03）、`ModuleMemoryStore`（F02）、提交四元组
  `(module_id, task_id, contract_revision, source_hash)`。

  一致性 = `integration_issues` 为空。

## 5. 关键设计

- **整体门禁**：`integration_issues` 汇总 F01 模块校验 + F03 接口校验 + 接口所有者存在 + 依赖存在 +
  **接口类型冲突**（同 capability 多签名）→ 非空则**整个 run FAIL**（`integration_ok=False`）。
- **可恢复提交状态机**：严格顺序 `STAGED→CODE_COMMITTED→INTERFACES_PUBLISHED→MEMORY_UPDATED→DONE`；
  越序即拒（不"先宣布成功后遗漏更新"）。
- **对账**：`reconcile` 检出**代码已提交但接口/记忆未落库**、**接口已记录但验证失败/未通过**、**提交未完成**。
- **回滚**：`rollback` 弃用该模块已记录接口、清空提交状态；**不修改老 ZIP**（老产物不动）。
- **验证绑定**：`verification_stale(commit, contract_revision, source_hash)` → 源码或契约变化使旧验证失效
  （承接 R19/R23 一致性；取消/预算/修复上限语义不变，本模块只提供门禁与状态机）。
