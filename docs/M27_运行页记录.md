## 后端接口（新增）

- `GET /api/runs/{id}`（`RunDetailView`）：`status`、`phase`（最近 `stage` 事件的阶段名，无则 null）、`tasks{total,done}`、`cost{currency_unit,settled_micro,reserved_micro,unknown_calls}`（**已结算 vs 预留分列**，未定价计 unknown）、`artifacts[{kind,path,sha256,verified}]`、终态时的 `verification`（读 run 目录 `verification.json`，逐项 `PASS/FAIL/NOT_RUN`）与 `error_code`。
- `GET /api/runs/{id}/events?after_sequence=N&limit=…`：`sequence > N` 增量事件，`payload` 为平台自身写入的 JSON（阶段名/哈希/错误码，**不含密钥**）；返回 `latest_sequence`。
- `GET /api/runs/{id}/artifact`：下载源码 ZIP。`find_artifact(kind="zip")` → `resolve_artifact_path`（**只按 `run_id` + 已记录路径构造，拒绝目录穿越**：产物必须落在本 run 目录内）→ `FileResponse`，`X-Artifact-Verified` 标注已验证/未验证。无产物或未产出 → `404 ARTIFACT_NOT_FOUND`。

三者均经 `require_run_owner`：非本人 `403`，不存在 `404`。

## 前端运行页

- 每 **2 秒**增量轮询：`GET /api/runs/{id}` + `GET /api/runs/{id}/events?after_sequence=<已收最大 sequence>`，只追加新事件；终态（`SUCCEEDED/FAILED`）后停止轮询。
- **失败退避**：连续轮询失败按 2s→4s→8s…（上限 30s）退避，成功即复位；**后台标签**（`document.hidden`）降频到 10s，回到前台立即拉取；401 清会话跳登录。
- 展示：状态标签 + 当前阶段；`已完成任务 done/total`（**无百分比**）；已结算/预留成本（微单位→元）与 UNKNOWN 提示；事件列表（序号/类型/脱敏 payload/时间）；失败时错误码 + 未通过项（含 `NOT_RUN`）标注；成功/失败均可下载 ZIP（未验证包显著标注“未验证”）。
- 生成后由项目页跳转到 `/runs/:id`。

## 验证（实测）

1. **后端**：`uv run --locked pytest` → **198 passed**（含 M27 新增 8 例）；`ruff check .` 全绿。M27 用例覆盖：详情 phase/tasks/cost/artifacts/verification、事件增量（`after_sequence`）、跨用户 `403` 与不存在 `404`、产物下载字节一致 + `X-Artifact-Verified`、缺产物 `404`、**目录穿越路径被拒**、失败包 `verified=false`。
2. **前端**：`npm ci` → `vue-tsc --noEmit` → `vite build` → `vitest run` → **5 文件 / 28 用例全部通过**（M27 新增 5 例：终态渲染并停止轮询；2s 轮询 + 增量事件只取新项；失败退避；失败展示错误码与 NOT_RUN 且无下载；未验证包标注）。
3. **真实后端 HTTP 全链路**（`uvicorn`，`RUNNER_WORK_ROOT` 指向临时目录；**不调用模型/Runner**）：
   - 提交运行 → `GET /runs/{id}` = `QUEUED`、`phase=null`、`tasks 0/0`、产物空、`verification=null`；`GET /events` = `[queued]`。
   - 以「worker 产出」方式写入 `run-<id>/source.zip` + `verification.json` 并落库任务/事件/产物/账本 →
   - `GET /runs/{id}` = `SUCCEEDED`、`phase=assemble`、`tasks 4/4`、`cost.settled_micro=1500000`、`artifacts[0].verified=true`、`verification.label=已验证`（`frontend_build=NOT_RUN`）；
   - `GET /events?after_sequence=0` = `[queued,claimed,stage,verification,packaged,succeeded]`，`after_sequence=3` 仅返回 `[4,5,6]`；
   - `GET /artifact` = `200`、`content-type=application/zip`、`X-Artifact-Verified: true`、字节数与磁盘 ZIP 一致；不存在 run → `404 RUN_NOT_FOUND`。
4. **另一账号下载被拒**：由后端用例 `test_artifact_download_serves_recorded_zip`、`test_events_and_detail_enforce_ownership` 断言 bob 对 alice 的 run 产物/事件返回 `403`。
5. **真实模型**：本步不触发任何模型调用（运行页只读、产物为本地模拟）；真实生成仍按 M25/M26 记 NOT_RUN。

## 剩余风险 / 阻塞

- 真实端到端 `生成 → Runner 构建/验收 → SUCCEEDED → 下载` 需 Docker Runner，属 M28 冷启动验收；本步以 worker 产出等价落库验证展示与下载契约。
- `verification` 报告按终态从 run 目录读取，文件缺失时返回 `null`（前端不误报）；平台与 worker 须共用 `RUNNER_WORK_ROOT`。
- Element Plus 全量引入的体积告警仍在（提示级）。
