日期：2026-10-12

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：以扩展适配器接通 `Asset Finder → MVP Resolver → asset-lock → M15 装配器`，支持已验证方法的
  直接 **COPY / 参数化 RENDER**，并保留失败时的**明确 Gap**（本步按开发者确认：**仅 COPY/RENDER**，
  STRUCTURED_EDIT 留待模板暴露方法扩展点后再启用）。
- **Context**：依赖 R06A—R06C 与已实现 M14/M15/M17/M18/M24；R07—R13 的新增业务能力优先经此流程查找；
  已有 Task MVP 继续可只用模板/能力包、无需 Method Unit。
- **Constraints**：先由完整模板/能力包占有已有 `provides/owned_paths`，方法不得重复实现认证/权限或覆盖原能力；
  引用冻结 `asset_id/version/checksum` 与索引快照元数据，运行期不动态换版本；只允许白名单扩展点的结构化植入；
  索引故障进入可解释阻塞/降级，不用未审核代码或静默越过必需检查；复用 R06A 版本化锁规则，旧锁不因新字段默认值改变字节/哈希。
- **WhenDone**：固定 Task 无额外方法时仍按 MVP 原路径生成/验收；含预审核方法的测试规格可通过 Finder
  锁定、装配并执行 Runner HTTP 回归；重复检索/装配可复现；未命中/冲突/无安全扩展点产生结构化 Gap 或错误而非文件覆盖；
  旧 `asset-lock.json` 仍能重放并校验。

## 输入 / 输出契约

- **规格**：新增可选字段 `method_requests: list[str]`（`id` 或 `id@version`；默认空 → MVP 路径不变）。
  为保持**旧 spec 冻结 hash 不变**，`method_requests` 为空时**不参与 canonical hash**（同 asset-lock 白名单思路）。
- **`resolve_lock(registry, profile, spec, contract, *, methods_root_path, index_path_override)`**（`method_lock.py`）：
  - 无 `method_requests` → 返回 `resolve_assets(...)` 的 **0.1 锁，字节/哈希不变**；
  - 有请求 → 逐项按 Finder 的确定性规则校验（`candidate_rejections`：Profile/语言框架/依赖/冲突/扩展点/许可证）
    + **路径不重叠**（比对能力包有效路径 `target_dir/owned` 与已选方法；模板宽泛工程根不比对，真正文件覆盖由装配器写重拒绝兜底）；
    - 任一不满足 → **结构化缺口**（抛 `ASSET_CONFLICT`，含 `未找到方法` / `path_overlap:*` / 其它理由）；
    - 全部满足 → 锁升 **`schema_version=0.2`**，写入 `method_units`（`id/version/checksum/path`）与
      `index_schema_version/index_revision/selection_reason`，按 0.2 字段集计算 `lock_hash`。
- **装配器 `assemble(..., methods_root=...)`**：对 `lock.method_units` 的 `src/**` 文件 **COPY** 到
  `target_dir`/`owned_paths[0]`；路径重复写入由 `_Writer` 拒绝（不覆盖原能力）；符号链接拒绝。
- **生成图**：`resolve_assets_node` 改用 `resolve_lock`（上下文新增 `methods_root`）；`assemble` 传入 `methods_root`。

## 设计

- **MVP 零漂移**：`method_requests` 默认空 → `resolve_lock` 返回与 `resolve_assets` **完全相同的 0.1 锁**
  （`model_dump` 相等、`lock_hash` 相同）；不请求方法即不改变任何既有字节/哈希。
- **按需升版本**：仅当确有方法入库才升 0.2，使 `method_units` 进入哈希、可 `verify_lock_hash` 防篡改；
  0.1 锁仍按原白名单哈希（旧锁重放不受影响）。
- **能力保护**：方法提供的能力不得与模板/能力包 `conflicts`；路径不得覆盖能力包业务区或彼此；实际文件覆盖由装配器拒绝。
- **可复现**：`lock_hash`/装配 `manifest_hash` 由内容派生；重复检索/装配结果一致。
- **Gap 而非覆盖**：任何未满足（未找到/不兼容/路径冲突）都抛结构化错误，绝不用相似代码或未审核代码补位。

## 风险 / 下一步

- **仅 COPY，不自动接线**：方法作为可复用类落入白名单路径，未改写业务代码；STRUCTURED_EDIT 需模板先暴露方法扩展点（后续步骤）。
- **方法选择来自规格显式请求**：`method_requests` 为显式输入，避免对隐式能力过度推断；R07—R13 的新增业务能力将优先经此流程。
- **spec hash 兼容**：`method_requests` 为空时排除出 canonical hash（既有 spec/contract 夹具与冻结 hash 不变）。
- **下一步 R07**：补充 Vue 3 + JavaScript Profile 分支（从 TS 基线派生，`is_supported_profile` 改为读取已发布 Profile 的确定性规则）。
