# M22｜LangChain 结构化需求提取

日期：2026-10-11  
状态：已实现并完成真实 DeepSeek API 验证；模型输出偶发结构不合格时按设计最多纠正一次，仍失败则保留人工可编辑草稿。

## 实现

- 使用 LangChain `ChatPromptTemplate` 和 `PydanticOutputParser` 形成 JSON 提示及严格解析；业务调用仍经 M21 `invoke` 计费网关，静态路由仅为 `user_interaction → deepseek_official/deepseek-flash`。
- `POST /api/projects/{id}/extract` 从项目原始中文需求提取候选；`GET /api/projects/{id}/spec` 可读取草稿、摘要、缺失字段和确认问题。未建立草稿时先创建可人工编辑的占位草稿，模型失败也不伪称成功。
- 官方 JSON 模式请求带 `response_format={"type":"json_object"}`，常规提取显式设置 `thinking.type=disabled`、输出上限 2048。仅结构/内容校验失败可再请求一次；每次独立预留、结算、留痕。
- 模型输出无法选择 Provider、模型、技术 Profile 或外部集成；程序固定 MVP Profile。所有模型提出的实体、权限、规则、验收项一律标 `pending`，只有用户显式编辑后才能成为 `user_confirmed`。来源文本及模型返回不执行命令、不访问其中的 URL、不读取密钥。
- 对字段/角色/动作进行白名单和安全标识符校验；中文 Task 常用术语按确定性表映射，规则/场景 ID 重新编号。确认前检查规格能编译为 Task 契约并进入固定能力包，阻止无法用于 M23 的规格冻结。
- 草稿有独立的编辑修订号：模型响应期间发生人工编辑或另一提取时，以条件更新返回 409，保留用户内容。确认前验证安全字段名、可搜索字符串字段和创建/读取角色；固定 Task 后端测试模板在能力包 `0.1.2` 按字段类型填充测试数据，旧资产版本不改。
- 模型账本在网络调用前以 SQLite 写锁原子检查并提交预算/次数预留，按完整 UTF-8 提示字节数加余量预留输入 token；在返回后提交 usage。Provider 返回体 `id` 可作为请求 ID。价格快照跟随调用保存，避免运行期间价格文件变化导致结算漂移；缺少密钥等明确未发出请求的失败会释放预留。缺少定价文件时成本为 `UNKNOWN` 并保留预算预留。
