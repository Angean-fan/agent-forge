## 契约内容（由 `schemas/task-management.spec.json` 编译）

- **数据库**：表 `task`；列 `id BIGINT PK`、`title VARCHAR(255) NOT NULL`、`description TEXT NULL`、`status VARCHAR(255) NOT NULL`、`owner_id BIGINT NOT NULL`、`created_at DATETIME NOT NULL`；`owner_id` 建索引。
- **REST 路由**（5 条）：
  - `GET /api/tasks`（list，返回列表）
  - `POST /api/tasks`（create，请求 `TaskCreateRequest`）
  - `GET /api/tasks/{id}`（get）
  - `PUT /api/tasks/{id}`（update，请求 `TaskUpdateRequest`）
  - `DELETE /api/tasks/{id}`（delete）
  - 均按权限矩阵标注 `allowed_roles`。
- **DTO**：`TaskCreateRequest`/`TaskUpdateRequest`（`title`(必填)、`description`、`status`(必填)）、`TaskView`（全部字段）。**主键/时间戳/归属列（`id`/`created_at`/`owner_id`）不出现在写入请求 DTO**，归属由服务端按登录用户设置，防止客户端伪造。
- **权限矩阵**：实体 `Task`；`ADMIN`/`MEMBER` 各含 `create/read/update/delete`（来自 spec.permissions）。
- **错误码**：`VALIDATION_ERROR(400)`、`UNAUTHORIZED(401)`、`FORBIDDEN(403)`、`NOT_FOUND(404)`、`CONFLICT(409)`、`INTERNAL_ERROR(500)`。
- **可追溯**：`spec_hash`（M07 冻结内容的 hash）、`profile_ref=demo-ts-mp@0.2`、`schema_version=0.1`、`contract_hash`。

## 设计要点

1. **确定性、可复现**：编译只做白名单类型映射（`long→BIGINT`、`string→VARCHAR(255)`、`text→TEXT`、`datetime→DATETIME`…）与固定命名规则（`Task→task`、驼峰→snake）；`contract_hash = SHA-256(规范化 JSON, 去掉 hash 自身)`，同输入恒等。
2. **冲突/不支持即拒绝（可解释）**：
   - 不支持的字段类型（如 `uuid`）→ `CONTRACT_UNSUPPORTED`，消息含类型名与位置；
   - 字段名归一化后冲突（如 `userName` 与 `user_name`）→ `CONTRACT_CONFLICT`；
   - 缺主键 `id`、多业务实体 → `CONTRACT_UNSUPPORTED`；角色权限重复 → `CONTRACT_CONFLICT`。
3. **不生成 CRUD 代码**：本步只产出契约数据（`BusinessContract`），业务实现留待 M11/M12 能力包按此契约渲染。
4. **不可被模型篡改**：契约由 Python 确定性生成；权限/验收来自冻结 spec，编译器不接受外部覆盖。
