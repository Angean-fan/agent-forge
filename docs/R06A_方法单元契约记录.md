# R06A｜扩展资产契约：可复用 Method Unit 类型

日期：2026-10-12
状态：完成（schema + Registry 读接口 + 锁版本化哈希；免费测试）
前置：R06（`886b13d`）；迭代文档 D2 的 R06A。

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：以**兼容 MVP 已发布资产**的方式扩展 manifest/schema 与 Registry 读接口，新增
  `Method Unit`（方法/类/片段）分类、稳定 ID、不可变版本与结构化调用契约。
- **Context**：依赖已完成 M08/M13/M14/M15 与 R06 冻结规格；现有 `AssetManifest`/`LockedAsset`/`AssetLock`
  均 `extra="forbid"`，旧锁哈希由模型序列化字段计算。本步为**新增工程增强**，非 MVP 补课；R06B 才建方法存储与索引。
- **Constraints**：保留原 manifest 字段与旧资产读取/锁格式；Method Unit 的
  `symbol/signature/layer/imports/preconditions/postconditions/side_effects/security_constraints/acceptance_ids/source_provenance`
  按新类型**严格验证**，不得用默认值掩盖缺签名/来源；`schema_version=0.1` 旧锁校验时用**原字段白名单**构造哈希输入，
  **显式排除新字段默认值**，不用全局 `exclude_unset`；新锁按新版本字段集计算；只允许声明已注册的安全扩展点；
  危险 `owned_paths`、许可证/来源不明者拒绝。
- **WhenDone**：旧 Task 的 Registry/Resolver/lock 与冷启动回归原样 PASS；用 MVP 基线的原版 `asset-lock.json`
  作回归夹具可**无需编辑**解析/哈希校验/按 ID+version+checksum 重放；新锁可解析且篡改被拒；最小 Method Unit
  通过检查，缺签名/非法依赖/未知 Profile/危险 `owned_paths`/冲突/无合法来源被拒。

## 输入 / 输出契约

- **`MethodUnitManifest`**（`kind="method-unit"`，`extra="forbid"`）：共有字段 + 结构化调用契约。
  **必需**（无默认，缺失即 parse 失败）：`symbol`、`signature`、`layer`（白名单）、`source_provenance`。
  可选：`imports`（安全模块名）、`preconditions`/`postconditions`/`side_effects`/`security_constraints`/`acceptance_ids`。
  `owned_paths` 由基类校验器拒绝绝对路径/`..`/盘符/反斜杠。
- **Registry 读接口**：`AssetRegistry._scan` 按 `kind` 分支解析（`method-unit` → `MethodUnitManifest`，其余 → `AssetManifest`）；
  `get/all/all_with_paths` 返回 `Manifest = AssetManifest | MethodUnitManifest`；`default_registry()` 本轮**无**方法单元（R06B 落地存储）。
- **`method_unit_issues(manifest, *, known_profiles, available_capabilities, present_capabilities, registered_extension_points)`**
  → 拒绝理由列表（空 = 通过）；**`require_valid_method_unit(...)`** 不通过抛 `ASSET_CONFLICT`（422，理由可追溯）。
- **`AssetLock`** 新增**可选**字段 `method_units: list[LockedAsset]`、`index_schema_version`、`index_revision`、`selection_reason`。
- **`lock_hash_of(lock)`** 按 `schema_version` 取**字段白名单**：`0.1 → (schema_version, profile, mysql_image, assets)`，
  未列版本按“全部字段（除 `lock_hash`）”。**`verify_lock_hash(lock)`** 重算不一致即 `ASSET_CHECKSUM_MISMATCH`（409）。

## 设计

- **兼容方式**：模板/能力包仍用 `AssetManifest`，字段与顺序不变（抽出 `_AssetBase` 承载共有字段）；方法单元用独立
  `MethodUnitManifest`，避免用默认值掩盖缺签名/来源。`kind` 分支解析，不污染旧资产语义。
- **锁版本化**：`model_dump()` 现在会带出新字段默认值，故 `lock_hash_of` 对 `0.1` **只哈希白名单字段**——
  与原实现（`model_dump()` 去掉 `lock_hash`）逐字节等价，旧锁哈希不变；新版本（如 `0.2`）按全字段集计算。
  未用 `exclude_unset`，不影响原字段序列化。
- **可追溯拒绝**：结构性错误（缺签名/危险路径/未知层）在 parse 阶段拒绝；上下文相关（Profile/依赖/冲突/扩展点）
  由 `method_unit_issues` 确定性判定并给出理由。`acceptance_ids` 预留给 R06C/D 的验收覆盖校验。
- **安全性**：`owned_paths` 仅描述可安装目标范围，不授予 Agent 任意目录权限；许可证/来源不明者拒绝发布。
