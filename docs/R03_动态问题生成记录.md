## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：用 **DeepSeek V4.1 Flash（`user_interaction`）** 依据已答信息与缺失/冲突项，一次生成 ≤3 个中文澄清问题，并输出未收敛字段与 `affects`。
- **Context**：依赖 R02 与 M21/M22 网关；`clients.py` 原仅下发 `thinking.type`、`ModelCall` 无 `reasoning_effort`。
- **Constraints**：为 `model_call` 增可空 `reasoning_effort`（向后兼容，旧行 NULL）；客户端/网关/账本**分别**传 `thinking_mode` 与 `reasoning_effort`，不把 `low/high` 塞进 `thinking_mode`；强度**仅对探针验证过的组合下发**，未验证即阻止启用（不静默丢弃）；普通缺失 → `disabled`，Python 断定明确冲突 → `enabled + low`；严禁改用 Qwen；不重复提问；不保存 `reasoning_content`。
- **WhenDone**：`disabled` 与冲突触发的 `enabled + low` 均有**真实接口探针和载荷/usage 证据**；支持与不支持强度的模拟响应均有断言；校园活动需求 ≤3 问题含 `question_id/affects`；无冲突已答字段不重复；路由只命中 `deepseek-flash`。

## 输入 / 输出契约

- **输入**：`missing_fields: list[str]`、`decisions: list[AnsweredDecision(affects, value)]`、当前未确认 `draft`（用于 `draft_id` 记账）。
- **输出**：`GeneratedQuestions{unresolved_fields, questions: list[Question(≤3)]}`（R02 模型）。
- **思考模式**：`detect_conflicts(decisions)` → 冲突存在则 `select_thinking_mode → ("enabled","low")`，否则 `("disabled", None)`；由 Python 决定，模型无权切换。

## 设计

- **强度门禁**：`_validate_thinking` 要求 `reasoning_effort∈{low,high}` 且必须与 `thinking=enabled` 同用，并须列入 `AGENTFORGE_VERIFIED_REASONING_EFFORTS`（探针通过后配置）；否则抛 `MODEL_UNAVAILABLE`，**不发起外部请求**、不静默降级。
- **生成**：LangChain `PydanticOutputParser` 解析为 R02 `Question`（≤3 题，`affects` 白名单、业务语言题面由 R02 校验）；最多一次结构纠正（同一次生成最多 2 次计费请求）；解析后按"已答且无冲突"确定性过滤重复题。
- **安全**：不保存隐藏思考（客户端只取 `content`，测试断言 `reasoning_content` 不入 `content`）；题面/选项做不安全指令过滤。

## 真实接口探针（已执行，5/5）

脚本：`scripts/deepseek_thinking_probe.py`（`SSL_CERT_FILE=/etc/ssl/cert.pem` + 真实 `DEEPSEEK_API_KEY`；
含瞬时网络重试）。实测证据（2026-10-12，`deepseek-flash`）：

| case | 请求参数 | HTTP | `reasoning_content` | content | 备注 |
|---|---|---|---|---|---|
| `default_none` | 不传 `thinking` | 200 | 有 | **无** | 128 输出 token 全被 reasoning 吃光 → 服务端**默认走思考** |
| `disabled` | `thinking.type=disabled` | 200 | 无 | 有 | 非思考路径正常 |
| `enabled_no_effort` | `thinking.type=enabled` | 200 | 有 | 有 | |
| `enabled_low` | `enabled` + `reasoning_effort=low` | 200 | 有 | 有/受限 | **low 被接受** |
| `enabled_high` | `enabled` + `reasoning_effort=high` | 200 | 有 | 有/受限 | **high 被接受** |

结论：`reasoning_effort=low/high` **均被官方 API 接受**（无 4xx）。据此 `AGENTFORGE_VERIFIED_REASONING_EFFORTS=low`
（本阶段启用 `low`；`high` 留给 R06，已在 `.env.example` 说明）。前两轮曾出现瞬时 `RemoteDisconnected`，
加退避重试后 5/5 且 `attempts=1`——属网络抖动，非 API 拒绝。

> ⚠️ **重要操作事实**：不显式传 `thinking` 时服务端**默认启用思考**（`default_none` 无 content）。
> 因此调用方**必须显式下发 `thinking.type`**（`disabled` 或 `enabled`）；本项目 `requirement_extraction`
> 与 `interview_generation` 均已显式下发。思考模式下 `max_tokens` 需覆盖推理预算，否则 `finish_reason!=stop`
> 会被网关判为未完成并重试（现有逻辑已如此）。
