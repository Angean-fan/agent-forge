## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：将装配计划与已冻结验收场景**逐项对比**，输出 `covered_acceptance_ids/uncovered_rules/gap_reason`；
  **仅对真实缺口**创建 `AGENT_PATCH` 任务；覆盖比较**同时消费 R06C/D 的方法级候选与拒绝证据**，区分“方法找到但不适配”与“真正没有方法”，

- **Context**：依赖 M13/M14、R13；技术文档第 4 节要求资产覆盖依据是**验收规则而非代码行数**；第 3 节明确**无缺口直接跳过 Agent**。

- **WhenDone**：已覆盖的标准 Task run **模型编码次数为 0**；用固定特殊规则构造的缺口能形成**可解释、可执行且路径有限**的 TaskPlan；
  对“已有适配方法”和“仅名字相似的错误方法”分别验证 coding 调用为 0 与产生**安全 Gap**。

## 设计

- **验收规则为唯一依据**：覆盖来自**冻结验收 ID** 的证据（方法声明 + 平台固定验收通过），不看代码行数/相似关键词。
- **区分两类缺口**：检索到候选但被拒（`candidate_incompatible`，附 `filter_reasons`）vs 无候选（`no_candidate`）；
  不确定即缺口，**不**标记完成、**不**放宽需求。
- **缺口有限可执行**：每条缺口给出 `allowed_paths`（按契约实体的服务/控制器层，非任意目录）+ 预期 `acceptance_id` + reason，供 R15 受限暂存后端消费。
- **无缺口跳过 Agent**：标准 Task / 校园活动主线在固定验收 PASS 下 0 缺口 → **不产生 AGENT_PATCH、0 coding 调用**。
