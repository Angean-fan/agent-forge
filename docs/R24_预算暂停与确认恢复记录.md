## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：实现 `PAUSED_BUDGET`、可追溯预算调整，以及 `POST /api/runs/{id}/resume` 的恢复流程。
- **Context**：依赖 R20/R23；预算不足**暂停**，增加本次预算并**明确恢复**后才能继续。
- **Constraints**：不允许系统默默换廉价模型或省掉测试；权限校验必须由 API 执行；恢复前核对未知预留和已提交检查点。
- **WhenDone**：低预算能真实暂停；未授权/未增加预算恢复被拒；授权增加预算后从安全检查点继续而非重复运行已提交任务。

## 输入 / 输出契约

- **`model.BudgetAdjustment`（迁移 `0014`）**：`project_id/run_id/delta_micro/reason/actor_id/created_at`；`budget.py` 提供 `effective_budget_micro = base + Σadjustments`、`record_adjustment`、`list_adjustments`。
- **`model_gateway.reserve`**：预算判定改用**生效预算**（基础额度 + 调整），预算不足抛 `BUDGET_EXCEEDED(402)`。
- **`RunStatus.PAUSED_BUDGET`（非终态）**：`PLANNING/GENERATING/VERIFYING → PAUSED_BUDGET`；`PAUSED_BUDGET → QUEUED`（恢复重入队）。
- **生成图**：捕获 `BUDGET_EXCEEDED` → 落 `PAUSED_BUDGET` + `paused_budget` 事件（**不换模型、不省检查**）。
- **`task_planning.plan_tasks`**：预算/调用/输出护栏错误**不再回退**为确定性计划，向上传播（触发暂停/拦截）。
- **`POST /api/runs/{id}/resume`**（归属 + CSRF）：仅 `PAUSED_BUDGET` 可恢复；`additional_budget_micro>0` 记入可追溯调整；核对状态不明调用（有则 409）；生效预算仍不足 → `402 BUDGET_EXCEEDED`；通过则 `PAUSED_BUDGET→QUEUED`、清租约、写 `resumed` 事件。
- **前端**：`PAUSED_BUDGET` 状态标签“预算不足已暂停”。

## 设计

- **暂停而非失败**：预算耗尽落 `PAUSED_BUDGET`（非终态），保留已有提交与账本；由用户经确认加预算后恢复，不在后台静默降级。
- **可追溯加预算**：每次恢复携带的增额逐条落 `budget_adjustment`（含 run、原因、操作者、时间）；生效预算 = 基础 + 累计调整。
- **权限与核对前置**：恢复需归属 + CSRF；恢复前拒绝“未加预算”（生效预算仍不足 → 402）与“存在状态不明调用”（→ 409 对账）；通过后仅**重新入队**，由 worker 从安全检查点续跑（R23 幂等节点保证不重复已提交任务）。
- **护栏不可绕**：预算/调用/输出限制不再被规划回退吞掉，确保“暂停/拦截”真实生效、不静默省检查。
