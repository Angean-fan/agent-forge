# E01｜建立 Integration Pack manifest 与版本发布策略

日期：2026-10-13
状态：完成（Mock-only 只读清单 + Resolver 锁定；免费/确定性测试）
前置：R12/R13、MVP M13/M14、R06A—R06D；迭代文档第二部分 E1 的 E01。

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：为第三方适配模板增加**只读 Registry**，定义 pack ID、版本、兼容 Profile、Port、Adapter、
  配置、Mock、校验和与许可证。
- **Context**：依赖 R12/R13 与 M13/M14 的资产注册机制；Integration Pack 作为**新增 `kind`** 复用
  `AssetRegistry` 寻址/`AssetLock` 锁定机制，**不另起一套搜索系统**。
- **Constraints**：选择**非支付、无真实外部凭据**的代表性模拟服务（本步：模拟天气查询）；不启用来源未验证的
  SDK（`source_provenance` 必需）；Agent 的一次性 patch **不自动升格**为公共资产（入库治理归 E10）。
- **WhenDone**：一个 Mock-only integration pack 可被 **Resolver 锁定**且通过 **Profile 兼容测试**；
  **重复、冲突与缺失依赖被拒**。

## 输入 / 输出契约

- **`IntegrationPackManifest`（`asset_registry.py`）**：复用 `_AssetBase` 字段
  （`id/version/kind/compatible_profiles/requires/provides/conflicts/parameter_schema/extension_points/
  owned_paths/checks/checksum/license`），额外**必需**：
  - `provider`（模拟/真实第三方服务名，安全标识）
  - `mode`（E01 仅 `"mock-only"`）
  - `ports: list[{name, methods}]`（业务侧只依赖的内部 Port）
  - `adapters: list[{name, kind}]`（E01 仅 `kind="mock"`）
  - `mock: {deterministic: bool, scenarios: [...]}`（mock-only 必须确定性）
  - `config: list[{env_name, required, secret, description}]`（E01 仅声明；申请/校验归 E03）
  - `source_provenance`（非空来源证明）、`target_dir`
  - 结构约束（`model_validator`）：拒绝 live 模式、非 mock adapter、非确定性 mock、
    **`required && secret` 的真实秘密**、空白来源、不明许可证（`license ∈ _FORBIDDEN_LICENSES`）；
    `owned_paths` 沿用基类危险路径校验。
- **Registry**：`_MODEL_BY_KIND` 按 `kind` 分支解析（`integration-pack` → `IntegrationPackManifest`）；
  新增只读根 `integration-packs/`（`DEFAULT_INTEGRATION_ROOT`）。**`DEFAULT_ROOTS` 不含该根** →
  生成默认注册表与既有 0.1 锁不受影响。`integration_registry()` 返回含集成包根的注册表。
- **`AssetLock`（`resolver.py`）**：新增可选 `integration_packs: list[LockedAsset] = []`；
  锁哈希白名单新增 **`0.2`**（冻结 R06A 字段集，排除新字段默认值）与 **`0.3`**
  （`schema_version/profile/mysql_image/assets/integration_packs/selection_reason`）。0.1/0.2 锁字节与哈希不变。
- **`resolve_integration_lock(registry, profile, requests, *, pins=None)`（`integration_lock.py`）**：
  - **无请求** → 返回 `resolve_assets(...)` 的 **0.1 锁，字节/哈希完全一致**（MVP 冷启动零漂移）；
  - **有请求** → 逐项按 Finder 的确定性规则校验（Profile 兼容 / 依赖 / 冲突 / 能力重复 / 路径覆盖），
    全通过后升 **`schema_version=0.3`**，写入 `integration_packs` 与 `selection_reason`，按 0.3 字段集计算 `lock_hash`；
  - 任一不满足 → **结构化错误**：未知包 `ASSET_NOT_FOUND`(404)、Profile 不兼容 `ASSET_INCOMPATIBLE`(422)、
    重复/冲突/能力重复/缺失依赖/路径覆盖 `ASSET_CONFLICT`(422)。**绝不静默补位或使用相似资产**。
  - `requests`：`<id>`（取最高版本）或 `<id>@<version>`；`pins` 与 `resolve_assets` 语义一致（复现）。

## 设计

- **MVP 零漂移**：集成包**不进入** `DEFAULT_ROOTS`；`resolve_assets` / 生成链路完全不变，
  `resolve_integration_lock(..., [])` 与 `resolve_assets` 的 `model_dump()` 与 `lock_hash` 完全一致。
- **版本化哈希**：按 `schema_version` 取字段白名单。0.1 锁哈希只含原字段集；0.2 显式列出 R06A 字段集
  （排除新 `integration_packs` 默认值）→ 旧锁字节/哈希不变；0.3 按自身字段集计算并可 `verify_lock_hash` 防篡改。
- **版本发布策略**：发布版本 = `(kind, id, version)` 三元组 + 目录 + `checksum`；已发布版本不可原地修改，
  变更须新增 `<version>` 并回填 checksum；选择默认取同 id 最高版本，`pins`/`id@version` 固定可复现。
- **能力/路径保护**：集成包 `provides` 不得与模板/能力包（或已选集成包）重复；`conflicts` 命中即拒；
  `target_dir/owned_path` 不得覆盖能力包业务区或彼此（模板宽泛工程根不比对，真正文件覆盖由后续装配兜底）。
- **Mock-only 安全边界**：解析期即拒绝 live/非 mock/非确定性/必需真实秘密/无来源/不明许可证；
  外部响应视为不可信数据（Adapter 归一化为内部 DTO，不向上传播供应商对象）。

## 费用 / 安全影响

- 费用：无模型调用；集成包为只读文件资产，无运行开销。
- 安全：清单**不接受**真实第三方密钥（`required && secret` 直接拒绝）；`source_provenance` 与
  许可证为发布硬门槛；`owned_paths` 沿用越界/绝对路径拒绝；集成包不影响既有生成资产选择与 0.1 锁。

## 剩余风险 / 下一步

- **未接入生成/装配链路**：本步只提供清单 + Resolver 锁定；由 Port 生成 Service 依赖、Adapter 实现、
  Mock 契约测试（成功/失败/超时）归 **E02**。装配器目前不 COPY 集成包文件（`integration_packs` 只入锁）。
- **配置项仅声明**：`config` 字段未生成 `.env.example`/指南，也未做同名变量冲突命名空间化 → **E03**。
- **状态区分**：运行报告尚未区分 `code_delivery_status` 与 `external_readiness`（Mock/Live）→ **E04/E05**。
- **版本策略实现为最小集**：默认取最高版本 + `pins` 固定；更细的发布审核流（来源/许可证独立审计）归 E10。
- **下一步 E02**：以本清单为输入，落 **Port/Adapter/Mock 契约链路**（生成 Service 仅依赖内部 Port，
  Mock 演示成功/失败/超时，且不宣称 Live 成功）。
