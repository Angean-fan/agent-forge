# R06C｜Asset Finder：精确检索、关键词召回与确定性兼容筛选

日期：2026-10-12
状态：完成（只读候选层；免费测试）
前置：R06B（`94cdeef`）；迭代文档 D2 的 R06C。

## 对应 Goal / Context / Constraints / WhenDone

- **Goal**：从 confirmed spec、冻结 contract 与 `acceptance_ids` 派生**规范化能力查询**；先按能力 ID/tag/技术栈
  **精确匹配**，再用 **FTS5 检索相近候选**，对 Template/Capability/Method Unit 统一做**可审计兼容筛选**。
- **Context**：依赖 R06A/R06B 与 MVP M13/M14；Finder 是 Registry/Resolver 之前的**只读候选层**，
  不依靠大模型选择真实资产；R06D 消费候选结果。
- **Constraints**：候选必须经 Profile、语言/框架、`requires/provides/conflicts`、参数、`extension_points`、
  许可证、权限/前后置条件及验收覆盖校验；排序固定可重复，返回 `EXACT/PARAMETERIZED/STRUCTURED_CANDIDATE/NO_MATCH`
  与拒绝原因；**关键词相似度只用于召回，不能替代语义/权限/接口证据**；不能确定即 `NO_MATCH`（转 gap）；
  **严禁偷偷调用 Qwen/DeepSeek 裁决**。
- **WhenDone**：对同一冻结查询返回稳定候选/版本/拒绝原因；可区分"没有检索到"/"检索到但 Profile 不兼容"/
  "候选兼容但业务语义或验收不足"；相似方法名、依赖冲突、权限不等价、不安全扩展点均不会被误选；
  未命中不伪装成成功。

## 输入 / 输出契约

- **`derive_capability_query(spec, contract) -> CapabilityQuery`**：确定性派生
  `{profile, stacks[(language,framework)], capability_ids, tags, required_acceptance_ids}`；
  **不读取原始需求文本**（能力 ID 来自 contract 结构，验收 ID 来自 spec）。`query_hash` 为**派生属性**（内容变化即变）。
- **`collect_candidates(registry, methods_root) -> list[Candidate]`**：Template/Capability Pack 取注册表真值，
  Method Unit 取方法仓库**权威 manifest**（跳过注册表中的 method-unit，避免两套真值）。
- **`find_assets(query, *, registry, methods_root_path, index_path_override, candidates) -> AssetSearchResult`**：
  - `candidate_refs`：精确（`provides ∩ capability_ids`）∪ FTS 召回（仅方法单元，`ref=method-unit:id@version`）；
  - `filter_reasons`：逐候选拒绝原因（`profile_incompatible`/`stack_mismatch`/`unmet_requirement:*`/`conflict`/
    `unregistered_extension_point:*`/`license_unclear`）；
  - `selected_refs`：通过筛选的候选（稳定排序 `(kind,id,version)`）；
  - `match_type`：`EXACT`（精确且非参数化）> `PARAMETERIZED`（精确但需参数化）> `STRUCTURED_CANDIDATE`（仅召回）> `NO_MATCH`；
  - `uncovered_acceptance_ids`：`required_acceptance_ids \ 选中方法声明覆盖`；
  - `index_revision`：取自索引 meta（审计用）。
- **`AssetSearchResult`** 记录 `query_hash/index_revision/match_type/candidate_refs/selected_refs/filter_reasons/uncovered_acceptance_ids`；
  查询仅含脱敏结构化条件，不保存用户原文。

## 设计

- **候选层只读**：不改资产、不写锁、不选最终版本；产出候选与理由供 R06D 的 Resolver 消费。
- **精确 ≠ 覆盖**：`provides ∩ capability_ids` 只表示"候选提供该能力"；是否满足业务语义仍看验收覆盖与 R06D 锁定，
  故 `match_type != EXACT` 或 `uncovered_acceptance_ids` 非空时明确暴露缺口。
- **召回不越权**：FTS 关键词命中仅决定"进入候选"，随后必须过 Profile/栈/依赖/冲突/扩展点/许可证确定性筛选；
  任一不通过即记录理由、不入选。
- **可区分三类**：候选为空 → `NO_MATCH`（没有检索到）；候选非空但全被拒且含 `profile_incompatible` →
  "检索到但 Profile 不兼容"；候选通过但 `uncovered_acceptance_ids` 非空/`match_type != EXACT` →
  "候选兼容但业务语义/验收不足"。
- **确定性**：能力 ID 全由 contract 结构派生（`crud`/`pagination`/`search`/`data_ownership`/`unique_constraint`），
  技术栈取自 Profile 的 `backend`/`frontend`；输出稳定可复现。

## 风险 / 下一步

- **候选选择仍未落地生成链路**：Finder 只给候选；接入 `Asset Finder → Resolver → asset-lock → 装配器`
  与失败时结构化 Gap 归 **R06D**。
- **权限/前后置条件校验偏结构**：`provides/requires/conflicts/extension_points/acceptance_ids` 已确定性地参与筛选；
  更细的"业务前后置/权限等价"证据随 R06D 装配与验收补齐。
- **能力 ID 派生范围**：当前仅从 contract 结构派生（`crud/pagination/search/data_ownership/unique_constraint`），
  不猜测隐含能力；新增能力类型需在同一处显式扩展。
- **下一步 R06D**：把方法索引接入既有 Resolver/装配器与 Asset Lock（COPY/参数化 RENDER/受约束 STRUCTURED_EDIT，
  旧锁仍可重放；未命中/冲突产生结构化 Gap）。
